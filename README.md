# DZExamsBot

بوت تيليغرام يقرّب محتوى موقع [dzexams.com](https://www.dzexams.com) للتلاميذ الجزائريين: دروس، فروض، اختبارات، ومواضيع شهادات (BEM / BAC)، بتصفح بسيط بالأزرار وبحث نصي.

> **ملاحظة:** هذا الإصدار إعادة كتابة كاملة للبوت بلغة **Rust** (بدل Python). الوظائف محفوظة كما هي: التصفح الهرمي، البحث، الفهرسة الخلفية، تدوير IP، وتجاوز حماية Cloudflare.

## ماذا يفعل

- تصفح هرمي: الطور (ابتدائي / متوسط / ثانوي / شهادات) ← السنة ← الشعبة (ثانوي وشهادات) ← المادة ← القسم (دروس، فروض، اختبارات…) ← الملفات.
- الشعبة **ترتّب ولا تُخفي**: ملفات شعبتك أولًا، ثم بقية ملفات المادة — كما يعرضها الموقع.
- ترتيب الملفات: الأحدث سنة أولًا، ثم رقم النموذج.
- ✅ بجانب الملف تعني أن الحل مرفق مع نفس الملف (الحل داخل الـ PDF، لا صفحة منفصلة).
- إرسال الـ PDF مباشرة عند الضغط على الملف، مع زر «رجوع» يعيدك لنفس صفحة القائمة.
- بحث نصي في كل المحتوى المفهرس: `/search كلمة`.
- فهرسة خلفية يومية تلقائية، وفهرسة يدوية للمشرف: `/indexall`.
- **نشر تلقائي للجديد**: ما يُفهرس حديثًا يُنشر تلقائيًا في قناة (`PUBLISH_CHAT_ID`) وإلى المشتركين (`/subscribe`).
- **زاحف مستقل**: `dzexams-crawler` (أو `dzexams-bot --crawl`) يملأ قاعدة البيانات دون تشغيل البوت — مناسب لـ cron.

## المتطلبات

- سلسلة أدوات Rust (rustup / cargo) — نسخة حديثة (تتطلب ~1.96+ بسبب الاعتماديات).
- توكن بوت تيليغرام (من [@BotFather](https://t.me/BotFather))
- معرف تيليغرام الخاص بك (لأوامر المشرف)

## التشغيل محليًا

```bash
git clone https://github.com/kerlif/DZExamsBot.git
cd DZExamsBot
cp .env.example .env
# ضع BOT_TOKEN و ADMIN_IDS في .env
cargo run --release
```

## متغيرات البيئة

| المتغير | الوصف | الافتراضي |
|---|---|---|
| `BOT_TOKEN` | توكن البوت | — (إلزامي) |
| `ADMIN_IDS` | معرفات المشرفين (مفصولة بفاصلة) | — |
| `DB_PATH` | مسار قاعدة البيانات SQLite | `dzexams.db` |
| `TMP_DIR` | مجلد الملفات المؤقتة | `/tmp/dzexams_bot` |
| `PROXY_LIST` | بروكسيات HTTP/SOCKS5 للخروج (اختياري، فاصلة) | — |
| `AUTO_INDEX_LEVELS` | الأطوار المفهرسة تلقائيًا يوميًا | — (معطلة إن لم تُضبط) |
| `AUTO_INDEX_HOUR` | ساعة الفهرسة التلقائية | `3` |
| `PUBLISH_CHAT_ID` | قناة/مجموعة النشر التلقائي (فاصلة لعدة معرفات) | — (معطل) |
| `PUBLISH_SUBSCRIBERS` | إرسال الجديد للمشتركين عبر `/subscribe` | `true` |
| `PUBLISH_MAX_PER_RUN` | أقصى عدد عناصر تُنشر في الدورة | `10` |
| `PUBLISH_INTERVAL_SECS` | الفاصل بين دورات النشر (ثوانٍ) | `600` |
| `SEARCH_RESULTS_LIMIT` | حد نتائج البحث | `10` |
| `WARP_FAIL_THRESHOLD` | عتبة الحجب المتتالي قبل تدوير IP | `3` |
| `WARP_WG_PROFILES` | أنماط ملفات WireGuard للتدوير | `/etc/wireguard/warp*.conf` |
| `USER_DL_COOLDOWN` | مهلة بين تحميلين لنفس المستخدم (ثوانٍ) | `10` |

## الاستضافة

البوت عملية دائمة (polling) مع قاعدة SQLite محلية — يحتاج منصة تشغّل عملية مستمرة وتحتفظ بملف قاعدة البيانات.

| الطريقة | الملفات | ملاحظات |
|---|---|---|
| **Docker** | `Dockerfile` | بناء متعدد المراحل (rust → debian-slim). شغّل الحاوية مع حجم عند `/app/data` واضبط `BOT_TOKEN` و`ADMIN_IDS`. |
| **VPS خاص** | `systemd/dzexams-bot.service` | ثبّت الملف التنفيذي في `/opt/dzexams-bot/dzexams-bot`، أنشئ المستخدم `botuser` وملّكه المجلد، انسخ الوحدة إلى `/etc/systemd/system/`، ثم `systemctl enable --now dzexams-bot`. تعمل بلا صلاحيات root. |

مثال Docker:

```bash
docker build -t dzexams-bot .
docker run -d --name dzexams-bot \
  -e BOT_TOKEN=... -e ADMIN_IDS=... \
  -v dzexams-data:/app/data \
  dzexams-bot
```

## كيف يصل البوت إلى الموقع

- الموقع محمي بـ Cloudflare. البوت يصل إليه بعميل HTTP عادي مع User-Agent `Mediapartners-Google` (ثغرة معروفة في الحماية) — إذا أغلقها الموقع يتوقف البوت عن الجلب ويُظهر رسالة خطأ واضحة، لا يفشل بصمت.
- المحتوى يُخزَّن كبيانات وصفية + روابط فقط؛ الـ PDF يُجلب فقط عند طلب مستخدم محدد، ولا يُنزَّل جماعيًا.
- ملفات ≥ 49MB تُرسل كرابط فقط (حد تيليغرام 50MB للبوتات) — يُفحص الحجم قبل الإرسال.
- مهلة 10 ثوانٍ بين تحميلين لنفس المستخدم (حماية من إغراق الموقع).
- سلسلة User-Agent احتياطية: إن حُجب الأساسي (Mediapartners-Google) يُجرَّب AdsBot ثم Googlebot.
- عند تكرار الحجب يُفعَّل تدوير IP عبر `warp-cli` أو ملفات WireGuard (`wg-quick`) أو `PROXY_LIST`.

## الزاحف المستقل والنشر التلقائي

الزاحف يملأ **نفس** قاعدة بيانات البوت (`DB_PATH`) دون تشغيل البوت، فتبقى واجهة البوت سريعة. كل عنصر جديد يُخزَّن بعلم «غير منشور»، ثم ينشره البوت تلقائيًا (قناة + مشتركين) عند أول دورة نشر.

```bash
# فهرسة كل الأطوار (أو AUTO_INDEX_LEVELS إن ضُبطت) ثم الخروج
dzexams-crawler

# فهرسة أطوار محدّدة
dzexams-crawler bac bem
dzexams-crawler bac,bem        # الصيغة نفسها بفواصل

# أو عبر البوت نفسه
dzexams-bot --crawl bac bem
```

مثال cron يومي (بعد منتصف الليل):

```cron
15 2 * * * cd /opt/dzexams-bot && ./dzexams-crawler >> crawl.log 2>&1
```

> لنشر الجديد إلى قناة، أضف البوت مشرفًا في القناة واضبط `PUBLISH_CHAT_ID` بمعرّفها. يمكن للمستخدمين أيضًا الاشتراك باستخدام `/subscribe` لتصِلهم ملخّصات الجديد في الخاص.

> ⚠️ إن ضبطت `PUBLISH_CHAT_ID` **قبل** الفهرسة الأولى، فسيُنشر الأرشيف كله تدريجيًا (`PUBLISH_MAX_PER_RUN` في كل دورة). للبدء من الصفر فقط: افهرس أولًا ثم اضبط القناة. العناصر الموجودة قبل إضافة ميزة النشر تُعدّ منشورة سلفًا.

## تغييرات عن نسخة Python

- أُعيدت الكتابة بالكامل بلغة Rust مع نفس السلوك والواجهة العربية.
- حُذف متصفح التحقق الاختياري (`stealth_browser.py` / Playwright) لأنه كان غير مستخدم، ولالتزام البناء بلا OpenSSL.
- حُذفت ملفات نشر Heroku/Render/Railway/Fly القديمة الخاصة بـ Python؛ بقي Docker و systemd.

## حدود معروفة

- الوصول يعتمد على User-Agent واحد — نقطة فشل واحدة إن أغلقها الموقع.
- بعض الملفات لا تتوفر على الموقع نفسه (صفحتها ترجع 403) — يظهر خطأ واضح.
- الفهرسة الكاملة لكل الأطوار تستغرق ~15–25 دقيقة وتُشغَّل يدويًا بـ `/indexall`.
